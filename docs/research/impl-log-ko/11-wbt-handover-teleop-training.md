# 11. 우리 원격조작 데이터로 VLA 4종 학습 (G1 WBT 병 건네주기)

- 기간: 2026-10-02 ~ 10-06
- 한 줄 요약: 실제 G1에서 GR00T-WBC로 직접 녹화한 "탁자의 음료병을 집어 건네주기" 데이터 43개 에피소드로 GR00T, Pi0.5, Psi0, XR-1을 학습했습니다. 각 모델은 공개 사전학습 가중치(base)와 우리 HE 체크포인트(he)에서 시작해 모두 8개를 학습했습니다. HE에서 시작한 모델이 대체로 더 정확했고, 미학습 에피소드 기준으로는 Pi0.5 he와 XR-1 he의 토큰, GR00T he의 손이 가장 좋았습니다. 50 Hz 정책을 실기에 보낼 수 있도록 스트리머도 고쳤습니다.

## 데이터

- 원본: `/mnt/data/jihun/datasets/G1_WBT_GR00T/handover_bottle_260930_subset_261002`. LeRobot v2.1, **50 Hz**, 43개 에피소드, 18,970 프레임, D435 머리 카메라 640×480 한 대입니다.
- 실제 로봇을 움직인 SONIC 토큰(`action.motion_token`, 64)과 측정된 로봇 상태가 이미 들어 있습니다. 측정 상태가 곧 SONIC이 도달한 자세이므로 [02](02-sim-deployment-prep.md)의 상태 재표기가 필요 없습니다.
- `prepare_wbt_sonic78.py`가 관절 이름으로 맞춰 sonic78 형식으로 바꿉니다.
  - 상태 28 = 팔 14 + Dex3 손 14 (측정값)
  - 액션 78 = SONIC 토큰 64 + 손 목표 14 (`action.wbc`)
  - 카메라 키는 HE 모델과 같은 `egocentric`으로 바꿔 HE 체크포인트를 그대로 이어 학습할 수 있게 했습니다.
- 녹화 데이터의 관절 이름이 우리 것과 같은 URDF 이름이라, 손 순서(왼손 엄지·중지·검지, 오른손 엄지·검지·중지)를 손으로 매핑할 필요가 없었습니다.
- 미학습 평가용으로 27번, 35번 에피소드를 뺐습니다(5 %).

## HE 체크포인트에서 시작할 때의 함정

LeRobot 학습 스크립트는 체크포인트에서 시작할 때 표준 정규화 단계의 통계만 새 데이터로 바꿉니다. 그래서 두 모델은 HE 데이터의 정규화를 그대로 들고 옵니다.

- GR00T는 통계를 자체 전처리 단계에 저장합니다.
- XR-1은 통계를 모델 버퍼에 저장합니다.

`retarget_init_checkpoint.py`로 학습 전에 시작 체크포인트의 전처리기를 새 데이터 통계로 다시 만들고, XR-1은 모델 통계도 다시 넣어 저장했습니다. 다시 만든 통계가 데이터와 정확히 같은지 확인했습니다.

Psi0는 따로 두 가지 문제가 있었습니다.

- **설정 파일:** Psi0는 체크포인트를 읽을 때 저장된 `config.json`에만 있는 `vlm_config`가 필요합니다. HE 학습 설정을 복사한 설정으로는 읽히지 않아서, 체크포인트의 설정을 그대로 정책 설정으로 썼습니다.
- **정규화 범위:** Psi0는 최소·최대값으로 정규화합니다. HE 데이터의 범위가 토큰은 약 2.7배, 팔 상태는 약 4.1배 넓어서, 새 통계로 바꾸면 HE 모델이 보던 값이 3~4배로 늘어납니다. 그래서 Psi0 he는 다른 he 모델과 달리 처음 손실이 높게 시작했습니다. 사용자는 새 데이터 통계를 그대로 쓰기로 했습니다.

| ----- | ----- | ----- |

| Pi0.5 | 0.021 | 0.017 |

### 미학습 에피소드 오픈루프 (27, 35번)

0.4초(50 Hz에서 20프레임)마다 다시 계획합니다. 노이즈 0이 모든 모델에서 같거나 더 좋아서 노이즈 0 결과만 적었습니다. 단위는 액션 std입니다.

| 모델       | 토큰 오차 | 토큰 경계 점프 | 손 오차   | 손 경계 점프 |
| ---------- | --------- | -------------- | --------- | ------------ |
| GR00T base | 0.332     | 0.191          | 0.068     | 0.124        |
| GR00T he   | 0.315     | 0.184          | **0.053** | **0.066**    |
| Pi0.5 base | 0.300     | **0.146**      | 0.079     | 0.172        |
| Pi0.5 he   | **0.284** | 0.151          | 0.106     | 0.115        |
| Psi0 base  | 0.303     | 0.162          | 0.077     | 0.092        |
| Psi0 he    | 0.303     | 0.170          | 0.089     | 0.075        |
| XR-1 base  | 0.316     | 0.171          | 0.173     | 0.147        |
| XR-1 he    | 0.287     | 0.158          | 0.168     | 0.132        |

- HE에서 시작하면 GR00T, Pi0.5, XR-1의 토큰 오차가 5~9 % 줄었습니다. Psi0는 위의 정규화 범위 문제 때문인지 차이가 없었습니다.
- XR-1의 손 오차는 다른 모델의 2~3배입니다. XR-1은 손을 측정 상태에 대한 상대값으로 예측합니다.
- XR-1 base는 랜덤 노이즈에서 쓸 수 없습니다(토큰 오차 0.645, 스텝이 녹화의 35배). 노이즈 0에서는 정상입니다.
- 토큰 오차는 HE 모델이 HE 미학습 에피소드에서 낸 값(0.13~0.15)의 두 배쯤입니다. 학습 41개, 평가 2개 에피소드라서 모델 간 차이(0.01~0.05)는 잡음 범위 안입니다. 시뮬레이션과 실기에서 판정해야 합니다.

평가 스크립트도 하나 고쳤습니다. 이 데이터에서는 오른손 thumb_0가 늘 0이라 std가 0입니다. 작은 std로 나누면서 XR-1의 상태 상대 오차가 130 std로 부풀어서, std가 0인 차원은 지표에서 빼도록 했습니다.

## 50 Hz 스트리머

실시간 카메라 모드의 스트리머가 30 Hz로 고정돼 있었습니다. 데이터셋 모드는 이미 데이터셋 주기를 따릅니다.

- `sonic_policy_streamer.py --policy-fps 50`을 추가했습니다. 기본값은 30이라 기존 모델은 그대로 동작합니다.
- 50 Hz에서는 20 ms 틱마다 청크 프레임에 정확히 맞고, 30→50 Hz 보간이 필요 없습니다.
- PC2의 스트리머를 새 버전으로 바꿨습니다. 이전 파일은 `sonic_policy_streamer.py.d1ce1c27`로 남겼습니다.
- `g1_groot_real_run.sh`에 `POLICY_FPS`, `POLICY_SUBDIR`, `BACKBONE_DTYPE`를 추가해 Pi0.5도 띄울 수 있게 했습니다.

## 시뮬레이션에서 50 Hz 경로 확인 (10-06)

h100_174의 공식 SONIC 시뮬레이션에서 미학습 27번 에피소드를 돌렸습니다. 정책 서버와 스트리머를 실기와 같은 방식(50 Hz, 플래너 자세 시작, 토큰 변화 제한 0.05, 노이즈 0.5)으로 띄웠습니다.

| 실행                | 손바닥 오차 중앙값 / p95 | 손목 오차 중앙값 | 최대 기울기 |
| ------------------- | ------------------------ | ---------------- | ----------- |
| GR00T he            | **3.7 / 9.7 cm**         | **7°**           | 8.0°        |
| GR00T he, 탁자 없음 | 4.3 / 10.7 cm            | 9°               | 8.7°        |
| Pi0.5 he            | 9.2 / 17.6 cm            | 32°              | 8.6°        |
| Psi0 he             | 4.2 / 20.3 cm            | 10°              | 9.1°        |
| XR-1 he             | 9.9 / 34.0 cm            | 28°              | 8.0°        |

- 50 Hz 경로가 끝까지 돌았습니다. 에피소드 475프레임 중 465프레임이 채점됐고, 청크 계산은 GR00T 0.19초, Pi0.5 0.27초였습니다.
- 처음에는 모든 실행이 중앙값 14 cm로 나왔습니다. 녹화 토큰을 그대로 재생해도 13 cm였습니다. 원인은 채점 기준이었습니다.
  - 기준으로 쓴 지령 관절값(`action.wbc`)은 PD 목표값입니다. 실제 로봇의 오른팔은 병을 들고 있어서 지령에서 약 9° 떨어져 있었습니다.
  - 시뮬레이션은 실제 로봇이 측정한 팔 관절을 1~3° 안으로 재현했습니다.
  - 그래서 기준을 측정 관절값(`observation.state`)으로 바꿨습니다.
- 폐루프 순위는 GR00T he, Psi0 he(중앙값은 GR00T와 비슷하고 큰 오차는 두 배), Pi0.5 he, XR-1 he(오른손이 벗어남) 순입니다. 오픈루프 토큰 오차는 Pi0.5와 XR-1이 가장 낮았지만 폐루프 결과와는 맞지 않았습니다.
- 탁자 유무는 결과에 영향이 없었습니다.

## 실기 준비 (10-06)

- GR00T he(12 GB)와 Pi0.5 he(EMA 가중치, 16 GB)를 워크스테이션 `/mnt/data/jihun/g1_models/wbt_*_he_full`로 옮겼습니다. Pi0.5는 12 GB GPU에 들어가도록 설정의 `dtype`을 bfloat16으로 바꿨습니다.
- 워크스테이션 RTX 3060에서 h100_174와 같은 오픈루프 결과가 나왔습니다(GR00T he 토큰 오차 0.315, Pi0.5 he 0.284).
- Pi0.5 서버가 실행 스크립트로 뜨는 것을 확인했습니다(GPU 1, 9.4 GB).
- 실기 시험은 사용자가 나중에 진행합니다. 과제 문장은 "pick drink bottle from the table and handover"이고, `POLICY_FPS=50`이 꼭 필요합니다.

## 실기 첫 주행 (10-08)

워크스테이션 GPU 0(포트 5561)에서 실행 스크립트 기본값(노이즈 0, 청크 블렌딩 0.3초)과 `POLICY_FPS=50`, 토큰 변화 제한 0.05로 돌렸습니다.

| ----- | -------- | ----- | ------------------------- | ----------- | -------- | ---------------------------------------- |
| 33~35 | GR00T he | 30초  | 0.011~0.015 / 0.013~0.014 | 1.17~1.62   | 239~309  | 병에 손을 뻗어 집고 건네주는 자세까지 함 |

- **GR00T he는 실기에서 과제를 수행했습니다.** 부드러움도 HE GR00T의 노이즈 0 + 블렌딩 주행(run24~27)과 같은 수준입니다.
- **Pi0.5 he는 시작하자마자 크게 움직였습니다.** 로봇의 오른손은 플래너 자세에서 쥔 상태로 시작하지만, 녹화 데이터 43개는 모두 편 손으로 시작합니다. Pi0.5의 두 번째 청크(약 0.3초)가 오른손을 한 틱에 1.67 rad 펴면서 팔도 크게 움직여 워치독이 에피소드를 끝냈습니다. 녹화 데이터에도 한 프레임에 손이 최대 1.78 rad 바뀌는 순간 전환이 있습니다. GR00T he는 손을 쥔 채로 시작해 정상적으로 수행했습니다.
