# 09. Unitree 데이터 손상 발견과 재학습

- 기간: 2026-09-30 ~ 10-01
- 한 줄 요약: Unitree 데이터셋에서 오른손 상태값이 ±3000까지 튀는 손상 프레임을 찾았습니다. 267개 프레임을 보간으로 고치고 통계를 다시 계산했습니다. 손상 데이터로 학습한 모델은 모두 지웠고, Unitree 재학습을 다시 시작했습니다.

## 발견

다른 작업(Psi0/XR-1 학습)을 하던 세션이 Unitree 데이터를 보다가 찾았습니다.

- 오른손 상태값(상태 차원 24~27)이 정상 범위를 크게 벗어나 ±3000까지 튀는 프레임이 있었습니다. 처음 찾은 건 39개 에피소드의 266개 프레임입니다.
- 이 값이 `meta/stats.json`의 상태 통계와 에피소드별 통계에도 그대로 들어가 있었습니다. 그 통계로 정규화하는 모든 정책이 영향을 받습니다.

관절 상태로 ±3000은 물리적으로 나올 수 없는 값입니다. 어디서 생겼는지는 아직 확인하지 않았습니다.

## 결정과 대기

사용자 결정으로 데이터를 고치고 모든 정책의 통계를 다시 계산하기로 했습니다.

수정은 Unitree 데이터를 읽는 학습이 없을 때 해야 했습니다. 마침 GPU 6에서 Unitree ACT 본 학습이 돌고 있었습니다. 그래서 이렇게 조율했습니다.

- 아직 시작하지 않은 Unitree 작업은 큐에서 빼서 대기 목록에 따로 뒀습니다.
- Unitree ACT가 끝나기를 기다렸다가 고쳤습니다.
- 데이터를 고치는 세션은 큐 파일, 큐 실행기, `.exit` 파일에 손대지 않기로 했습니다.

## 손상 데이터로 학습한 모델 삭제

사용자 결정으로 손상 데이터로 학습한 모델을 모두 지웠습니다(10-01).

- H100: 공식 레시피로 학습한 Unitree GR00T와 ACT. 로그는 `*.corruptdata`로 이름을 바꿔 남기고, 두 작업을 다시 큐에 넣었습니다.
- 워크스테이션: 결합 GR00T(Unitree + HE, run01~03에서 쓴 모델)와 Unitree 78D GR00T 사본.

[02](02-sim-deployment-prep.md)~[04](04-first-real-robot-runs.md)의 Unitree 모델 결과(시뮬레이션 순위, 결합 학습 비교, run01~03)는 이 프레임이 들어간 데이터로 학습한 모델에서 나왔습니다. 기록은 남겨 두되, 모델은 더 이상 없습니다. HE 모델은 HE 데이터만 썼으므로 영향이 없습니다.

## 재학습 재시작

- 대기 목록의 작업을 두 큐에 다시 붙이고 GPU 6 실행기를 재시작했습니다.
- Unitree GR00T가 고친 데이터로 10-01 10:30 KST에 다시 학습을 시작했습니다. 이어서 GPU 6에서 Unitree ACT와 Diffusion이 돕니다.
- GPU 0의 Unitree 작업(Pi0.5, VLA-JEPA, MolmoAct2, FastWAM)은 HE MolmoAct2와 FastWAM이 끝난 뒤에 돕니다.
