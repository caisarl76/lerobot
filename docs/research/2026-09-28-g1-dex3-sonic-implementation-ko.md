# G1 Dex3·SONIC 구현 작업 기록

**기준일:** 2026-09-28

**범위:** 2026-09-22부터 09-28까지 이 저장소에서 진행한 G1 Dex3 데이터, 정책 학습, SONIC 제어 및 실기 배포 준비. 수치는 별도 표시가 없으면 기록된 오프라인 검사 또는 MuJoCo 시뮬레이션 결과다. 실제 로봇에서 정책으로 테이블 작업을 수행한 결과는 아직 없다.

## 목표와 현재 상태

Unitree G1 Dex3의 팔 14관절과 손 14관절로 이루어진 **28D 작업 데이터**를 여러 VLA 정책의 학습 데이터로 만들고, 정책 출력을 NVIDIA GEAR-SONIC v1.1을 통해 G1에 전달하는 경로를 구축했다. 이를 위해 28D 관절 명령을 미리 SONIC 토큰으로 인코딩한 **78D 정책 경로**와, 28D 정책 출력을 실행 시점에 인코딩하는 **28D 경로**를 모두 구현했다. 78D는 SONIC 토큰 64개와 SONIC을 거치지 않는 Dex3 손 관절 14개다.

현재까지 두 경로의 데이터 계약과 시뮬레이션 동작을 확인했다. 78D 경로에서는 여러 정책을 비교해 GR00T을 우선 실기 후보로 골랐고, 28D GR00T도 두 개의 미학습 평가 에피소드에서 균형을 유지했다. 로봇 PC2의 카메라·스트리머와 원격 GPU의 정책 서버를 분리했고, 초기 배포용 감시 장치까지 추가했다. **실제 로봇의 폐루프 정책 실행, 실제 네트워크 왕복 시간, 실제 카메라 영상의 학습 데이터 적합성은 다음 검증 단계다.**

| 시기 | 완료한 이정표 |
| --- | --- |
| 09-22~23 | Unitree 13개 수집 데이터의 28D 통합, SONIC 78D 변환, 정책별 학습 설정과 데이터 계약 검증. |
| 09-23~25 | SONIC 왕복 오차 분석, 변환 속도 제한 해제, 30→50 Hz 토큰 스트리밍, 기본 정책 학습·평가. |
| 09-25~27 | SONIC 도달 상태로 재표기해 재학습, 테이블 회피 시작·복귀 경로, 공식 배포 시뮬레이션 순위, 원격 정책 서버. |
| 09-28 | 28D 온라인 인코딩, Unitree+HE 결합 학습, PC2 카메라·경량 스트리머, 첫 배포 감시 장치와 시뮬레이션 검사. |

## 구현 흐름

```text
Unitree 13개 수집 데이터 ─┐
                        ├─ 28D 데이터 검증·통합 ─ SONIC v1.1 인코딩 ─ 78D 데이터
Humanoid Everyday ──────┘                         │
                        └─ 28D 정책 학습            └─ 78D 정책 학습
                                  │                         │
                                  └─ 실행 시 인코딩 ────────┤
                                                            ▼
실시간 머리 카메라 + G1 관절 상태 → 정책 서버 → 30 Hz 액션 청크 → 50 Hz 토큰 스트리머
                                                        → NVIDIA C++ SONIC 디코더 → G1
```

- **데이터 준비:** 13개 Unitree 데이터셋의 3,152 에피소드와 Humanoid Everyday(HE)의 4,064 에피소드를 각각 검증하고 변환했다. Unitree 원본의 카메라 축 표기, 에피소드 메타데이터, 작업 문구 오류를 파생 데이터에서 바로잡되 원본은 보존했다. 결함이 확인된 Unitree 통합 에피소드 2202는 학습에서 제외했다.
- **학습:** ACT, Diffusion, GR00T N1.7, Pi0.5, MolmoAct2, VLA-JEPA, FastWAM의 7개 정책을 비교했다. 원래 관절 상태와 SONIC이 실제 도달한 팔 상태로 다시 표기한 데이터 모두에서 5% 미학습 에피소드를 분리해 학습했다. 별도로 28D GR00T과 Unitree+HE 단일 카메라 결합 데이터의 GR00T·Pi0.5·MolmoAct2를 학습했다.
- **실행:** 정책 서버는 이미지·관절 상태를 받아 청크를 추론한다. 로봇 쪽 스트리머는 SONIC 변환(28D인 경우), 30→50 Hz 선행 보간, 테이블 앞 시작·복귀 경로, 제어 게이트와 상태 감시를 맡는다. 실제 로봇용 스트리머는 PyTorch 없이 동작하도록 분리했다.

## 검증 결과와 해석

### 변환·학습

- SONIC 속도 제한을 끈 Unitree 데이터는 **3,152 에피소드 / 2,587,515 프레임**, HE 데이터는 **4,064 에피소드 / 1,779,287 프레임**이다. SONIC 토큰은 몸체를 나타내고 Dex3 손은 관절 값 그대로 전달한다. 변환은 팔·손만 있는 원본 데이터에 고정된 기본 서기 자세의 다리·허리 값을 보충한다.
- 28D 청크를 온라인에서 인코딩한 결과는 전체 에피소드 기준 저장된 토큰과 **100% 동일**, 40프레임 이상 청크·0.4초 재계획 기준 **99.98% 동일**했다. 30프레임 청크는 **99.57%**였다. 차이는 불일치 지점에서 토큰 양자화 한 칸 이하였다.
- 7개 정책의 Unitree·HE 기본 및 상태 재표기 실행을 완료했고, 14개 기본 실행은 로드·예측과 오픈루프 미학습 평가를 수행했다. 오픈루프에서는 ACT의 오차가 가장 낮았지만, 시뮬레이션 폐루프에서는 GR00T이 앞섰다. VLA-JEPA는 학습 데이터에서도 큰 예측 오차가 남아 성공 모델로 취급하지 않는다.
- Unitree+HE 결합 데이터는 **7,216 에피소드**를 공통 단일 카메라·재표기 상태로 묶었다. GR00T, Pi0.5, MolmoAct2를 각각 40,000 스텝 학습했다. 결합 모델을 출처별로 평가하는 `ho5_openloop_eval.py`를 저장소에 추가했으나, 이 문서 작성 시점에 **세 모델의 출처별 평가 수치가 기록된 문서는 없다**.

### 폐루프·배포 준비

| 비교 조건 | 관찰 결과 | 해석의 범위 |
| --- | --- | --- |

오픈루프 정책 오차와 폐루프 작업 성능은 같은 순위를 보이지 않았다. 특히 기록된 이전 액션을 반복하는 기준선이 짧은 예측 지평에서는 많은 정책보다 정확했으므로, 이미지와 상태만으로 현재 액션을 복원하는 능력이 병목일 가능성이 있다. 이는 후속 입력 설계 실험의 근거이며, 현재 원인이 확정된 것은 아니다.

## 진행 현황과 다음 단계

1. **실기 첫 폐루프 실행:** PC2의 전용 카메라 발행기와 스트리머, 워크스테이션 또는 H100의 정책 서버, NVIDIA 제어기를 연결한다. VPN 경로의 실제 지연·타임아웃, 50 Hz 송신, 카메라 색상·시야·노출을 먼저 측정한 뒤 테이블 앞 시작→정책→플래너 복귀를 검증한다. `--max-token-step 0.05`와 관절 감시 로그를 함께 확인한다.
2. **결합 모델 비교 완료:** GR00T·Pi0.5·MolmoAct2의 Unitree/HE 출처별 미학습 오픈루프 결과를 기록하고, 결합 GR00T의 두 에피소드 시뮬레이션을 기존 2카메라 모델과 같은 조건에서 비교한다. 현재 결합 모델의 수치 근거는 GR00T의 제한된 시뮬레이션 실행뿐이다.
3. **28D 경로 추가 검증:** 에피소드 2155를 반복하고 미학습 에피소드 3–5개를 늘려 왼손 오차가 일관된 차이인지 확인한다. `joint28` 분위수 통계를 고친 뒤 Pi0.5 등 28D 정책을 학습하고, 28D 상태도 SONIC 도달 자세로 다시 표기하는 실험을 진행한다.
4. **장기 병목 해결:** 정책 입력에 이전 액션을 포함하는 실험을 설계하고, VLA-JEPA의 묶인 가중치 로드 검사와 낮은 학습 성능을 분리해 조사한다. 테이블 전면 덮개, 작업별 초기 포즈, Dex3 손의 실제 추종 성능도 별도 검증한다.
